## What changed against #17

- **Hide / unhide now re-renders (F1).** #17 wrote the marking cuts (`CutRange`) and hides (`Hidden`) with
  `BatchesUpdated` from the paint system, which runs in PreCulling AFTER the game's `PreCullingSystem`. The game reads
  `BatchesUpdated` only in `PreCullingSystem` (PreCullingSystem.cs 2428-2436, 652, 1895) and strips the tag at the end
  of the same frame (PrepareCleanUpSystem.cs 29-40, CleanUpSystem.cs 24-31 / 53), so the change was probably never
  drawn until something else touched the road. The writes now run in a new `MarkingRenderSystem`, registered
  `UpdateBefore<MarkingRenderSystem, PreCullingSystem>(PreCulling)`. The paint system only posts "apply" / "clear"
  requests and they are carried out before the next `PreCullingSystem`, so there is a delay of one frame.
- **A failed save strip is never silent (F2).** Before a save each cut is taken off. A failure is retried once. If it
  still fails, the cut list is emptied in place (an empty list draws the whole lane). If that fails too, the log says
  CRITICAL "THIS SAVE MAY CONTAIN HIDDEN ROAD MARKINGS" with counts. A retry that works is logged as a WARN.
- **Clear during a save (F3).** If a box is removed or the setting is switched off between the save strip and the
  restore on the next frame, the markings are now redrawn and the pending restore is dropped.
- **Mod unload (F4).** `Mod.OnDispose` switches painting off and puts the markings back straight away
  (`PaintControl.Shutdown`).
- **Tests (F6).** The bookkeeping (strip, restore, clear, fallbacks) moved to `Core/MarkingLedger.cs` and gets
  behaviour tests on a fake world (`MarkingLedgerTests`).
- **Setting "Hide road markings under yellow boxes" now defaults OFF.** #17 hid markings by default with a render
  path that did not refresh, and with a save strip that could fail silently. The owner should switch it on only for
  K1/K2 below. If both pass, the merger can decide whether the default goes back to on.

## Log lines

- `yellow boxes: road markings under the boxes hidden: N marking lane(s) cut, M marking object(s) hidden[; left alone ...]; x ms`.
  The render system writes this on every apply.
- `yellow boxes: road markings under the boxes shown again`: a clear (setting off, last box gone, paint off, unload).
- `... needed a fallback, the save is clean ...` (WARN), or CRITICAL `... THIS SAVE MAY CONTAIN HIDDEN ROAD MARKINGS ...`.

## Owner checks in game (setting ON for these)

- **K1, saves stay clean.** Switch the setting on in a city with boxes, check the markings under the boxes are gone,
  then save. Quit, disable or remove Junction Rules, and load that save. The markings under the old box places must be
  intact (lane lines, arrows, painted numbers), and the save log must have no CRITICAL line.
- **K2, immediate.** With the setting on, add a box: its markings vanish at once, with no camera move or road edit
  needed. Remove the box: they come back at once. Toggle the setting off and on: the markings return and vanish at
  once. Do it once right after a save as well (strip/restore path).
